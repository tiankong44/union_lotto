# 血压双输入框设计

## 目标

将记录中心的血压录入从一个“高压/低压”文本框改为高压、低压两个独立输入框，使录入字段与业务含义一一对应，同时保持现有健康记录接口和数据库表结构不变。

## 用户交互

- 选择“血压”时显示“高压”和“低压”两个必填数字输入框。
- 两个输入框仅校验是否填写、是否为可解析的非负数；医学有效范围待补充，不在本次需求中推断。
- 选择体重或症状时继续显示原有单值输入框，记录时间、单位、备注和保存状态保持现状。
- 保存失败时保留当前输入，保存成功后清空表单并恢复当前记录时间。

## 数据契约

血压继续通过现有健康记录保存接口提交，`valueJson` 使用以下结构：

```json
{"systolic":"高压值","diastolic":"低压值"}
```

单位继续提交 `mmHg`。体重和症状仍使用现有的 `{"value":"..."}` 结构，后端 DTO、实体和 `pregnancy_health_record` 表不变。

## 展示与范围

- 历史记录和身体记录时间线解析血压 JSON，并显示为“高压 / 低压”。
- 体重、症状以及其他记录的现有展示和保存逻辑不改变。
- 不新增高低压医学判断、提醒阈值、数据库字段、接口字段或历史数据修复脚本。

## 风险与验证

- 若只修改录入而不修改展示，新结构化 JSON 会直接暴露给用户，因此历史页和时间线必须同步调整。
- 通过前端类型检查、生产构建和关键字段静态检查验证；不进行真实数据库写入联调，不使用浏览器视觉验证。
