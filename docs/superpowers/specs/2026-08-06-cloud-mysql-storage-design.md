# 云端 MySQL 存储改造设计

## 目标

将孕期助手及后端上传文件的业务持久化统一到云端 MySQL，浏览器不再保存快照或同步队列，服务端不再把新上传文件写入本地业务目录。

## 数据流

- 前端首次进入时并行调用孕期档案、胎动、宫缩、健康记录和待办查询接口。
- 新增或更新操作先调用后端 CRUD 接口，MySQL 写入成功后才更新 Pinia 内存状态。
- 网络不可用或云端请求失败时不落本地数据，保留当前表单内容并提示重试。
- `clientRecordId` 继续作为记录幂等键；本地同步批次不再参与业务流程。

## 接口与存储

- 保留 `/tabs/pregnancy` 下的档案、胎动、宫缩、健康记录和待办 CRUD 接口。
- 移除 `/tabs/pregnancy/sync` 以及同步 DTO、实体和服务逻辑。
- 新增 `/tabs/common/files` 上传接口和 `/tabs/common/files/{fileKey}` 下载接口。
- 文件元数据与最多 10 MB 的图片内容保存到 MySQL `cloud_file` 表，文件编号使用随机值。
- 不迁移旧浏览器数据，不迁移或删除历史磁盘文件，不新增账号和用户隔离模型。

## 失败与验证

- 加载失败时页面显示云端加载错误，不回退浏览器缓存。
- 保存失败时不更新业务列表，页面保留输入并允许重试。
- 通过前端类型检查、生产构建、Java 编译、SQL 禁止项检查和本地存储引用扫描验证。
