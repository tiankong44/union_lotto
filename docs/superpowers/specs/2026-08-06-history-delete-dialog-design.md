# 历史记录删除确认弹层设计

## 目标

将历史记录删除时的浏览器原生确认框替换为页面内自定义确认弹层，提升视觉一致性和移动端可用性，同时保持现有删除接口、失败保留和单条删除规则不变。

## 设计

- 在 `RecordsView.vue` 内维护当前待确认记录的类型和客户端编号。
- 点击删除按钮只打开弹层，不立即调用删除接口。
- 弹层包含删除提示、取消按钮、确认删除按钮和关闭按钮；点击遮罩、取消或关闭按钮均只清理待确认状态。
- 确认后复用现有 `deletingRecordKey` 调用 store 删除方法，确认按钮进入处理中状态并阻止重复提交。
- 删除成功后沿用现有备注编辑清理逻辑；请求失败时关闭弹层并沿用当前记录错误提示，保留列表项。

## 范围

- 修改：`pregnancy-assistant/src/views/RecordsView.vue`、`pregnancy-assistant/src/styles.css`。
- 不修改：后端删除接口、数据结构、记录筛选、删除权限和关联数据清理逻辑。
- 不新增通用组件，因为当前只有历史页使用该确认交互，新增公共抽象会扩大本次改动范围。

## 验收

- 删除按钮不再调用 `window.confirm` 或浏览器原生确认框。
- 取消、关闭和遮罩点击不会触发删除请求。
- 确认删除只触发一次；处理中状态下确认按钮不可用。
- 删除失败时记录仍保留，并展示现有错误信息。
- `npm run type-check` 和 `npm run build` 通过。
