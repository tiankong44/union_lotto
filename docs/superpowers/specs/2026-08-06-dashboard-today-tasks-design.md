# 总览当天安排与待办跳转设计

## 背景

当前总览的待办摘要只显示全部未完成事项数量，“今天的安排”也从全部未完成事项中直接截取前三条，因此可能把未来事项展示在当天区域。待办真实页面已经由 `/tasks` 路由承载完整列表，本次只需要收紧总览口径并补充可达入口。

## 目标

- 总览待办数量统计所有状态为待处理的事项。
- 总览当天安排只展示计划时间处于用户本地当天、且状态为待处理的事项。
- 总览待办摘要、当天安排列表和空态入口均可进入真实待办页面 `/tasks`。
- 待办页面继续展示完整事项，不改变事项新增、完成、取消或删除行为。

## 非目标

- 不新增接口、数据库字段、路由或待办状态。
- 不修改待办页面的完整列表、表单和状态切换逻辑。
- 不引入提醒阈值、医疗判断或新的业务规则。

## 交互设计

### 总览摘要

“待办事项”指标改为可访问的路由链接，数量表示全部待处理事项数量。点击指标进入 `/tasks`，不在总览直接改变事项状态。

### 当天安排

“今天的安排”使用同一份当天待处理事项数据，按 `plannedAt` 升序展示；每条事项使用路由链接进入 `/tasks`。没有当天事项时保留空态，并提供进入 `/tasks` 添加或查看事项的入口。

### 日期口径

前端使用浏览器本地时区比较 `plannedAt` 的年、月、日。无效计划时间不进入总览当天列表，但仍保留在待办页面，由完整列表负责展示。

## 数据流与边界

现有 Pinia store 继续负责加载 `tasks` 和计算 `pendingTasks`。总览页面使用 `pendingTasks.length` 作为摘要数量，另用局部计算属性从 `pendingTasks` 过滤当天事项并排序；待办页面继续直接使用完整任务集合。摘要和当天列表因此保持不同口径，待办页面的完整内容不会受总览限制影响。

## 验收标准

- 存在未来待处理事项时，总览当天区域不展示该事项。
- 存在未来待处理事项时，总览指标数量包含该事项。
- 存在今天的待处理事项时，列表按计划时间排序；指标数量始终等于全部待处理事项数量。
- 点击总览数量、单条事项和空态入口都能进入 `/tasks`。
- 已完成事项不计入总览当天事项。
- 前端类型检查和生产构建通过。
