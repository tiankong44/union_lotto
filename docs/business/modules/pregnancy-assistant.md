# 孕期助手模块

# 模块基本信息
- 模块编码：`pregnancy-assistant`
- 模块名称：孕期助手
- 所属业务域：孕期健康记录
- 负责人：待补充
- 当前版本：v1
- 更新时间：2026-08-06
- 依赖模块：胎动记录、孕期健康记录、产检待办、统计分析、提醒

# 业务定位 & 作用
- 模块职责：提供个人孕期信息、健康记录、时间线、统计和云端保存入口。
- 解决的问题：将分散的孕期记录集中保存，并支持手机、平板和电脑查看。
- 不做会怎样：用户难以连续回看自身记录，也难以整理就医沟通资料。
- 目标用户/使用角色：孕妇本人，首版只有一个使用者。

# 核心业务流程
1. 前置条件：用户首次进入工具，云端 MySQL 服务可用。
2. 主流程步骤 1：建立或更新孕期档案，录入末次月经日或预产期等信息。
3. 主流程步骤 2：用户从记录中心或对应页面记录胎动、宫缩、体重、血压和症状，并单独管理产检事项。
4. 主流程步骤 3：胎动和宫缩在用户点击结束后自动通过后端接口保存到云端 MySQL，其他记录按表单提交保存。
5. 主流程步骤 4：用户可在历史记录列表补充、修改或清空各类记录备注。
6. 分支流程：用户查看历史、按 7/30/90 天统计个人趋势、查看身体记录时间线、导出或设置提醒。
7. 异常流程：网络或云端写入失败时不保存记录，保留当前会话或表单并提示重试；明显变化只提示联系产科。
8. 流程结果：形成可查询、可统计、可导出的个人孕期记录。

# 功能清单
- 孕期档案：待产期、孕周、胎儿数量、备注。
- 记录中心：集中提供宫缩、体重、血压和症状入口，胎动与产检待办保留独立页面。
- 查看功能：日历、时间线、单日详情和历史筛选。
- 记录备注：胎动、宫缩、健康记录和待办均可在历史列表补充、修改或清空备注。
- 统计分析：胎动按时间分布、体重趋势、身体记录时间线、个人趋势和记录完整度。
- 辅助能力：提醒、云端刷新、导出和设置。

# 原始业务需求
- 业务方原话：新增一个 Vite+Vue 前端项目，用来记录孕期胎动，并完善查看、统计、分析、后端和数据库。
- 需求背景：现有工具后端没有孕期记录模型和前端入口。
- 用户角色：单一使用者。
- 业务目标：提供跨电脑、手机、iPad 的响应式孕期记录工具。
- 提出时间：2026-08-06。

# 业务规则 & 约束
- 状态流转规则：记录经历云端加载、保存中、云端已保存或保存失败。
- 金额 / 数量规则：涉及数值字段的有效范围和单位仍需结合医疗业务确认，超出范围时拒绝保存并提示用户。
- 时间规则：记录时间使用用户本地时区保存展示，服务端保存可追溯时间。
- 录入规则：健康记录默认当前本地时间，允许用户修改记录时间用于历史补录。
- 自动保存规则：胎动和宫缩只在用户点击结束后自动提交，不使用设备传感器识别，不因目标次数达到而自动提交。
- 备注规则：胎动和宫缩计时页不要求填写备注，备注统一支持在历史列表后续维护。
- 报表规则：报表默认查看最近 30 天，并支持切换最近 7 天或 90 天；按自然日分组时使用用户本地时区。
- 权限规则：第一版只有一个使用者，不提供账号、用户隔离和共享权限。
- 禁止事项：不输出疾病诊断，不使用统一次数阈值替代医生建议，不把提醒当作医疗结论。
- 补充约束：数据删除、保存期限、云端备份恢复和访问控制待补充。

# 关联模块 & 上下游
- 上游模块：用户输入、孕期前端云端接口。
- 下游模块：胎动记录、孕期健康记录、产检待办、统计分析、身体记录时间线、提醒。
- 接口依赖：孕期档案 CRUD、记录 CRUD、记录备注更新接口、统计接口和导出接口。
- 消息队列 / 事件依赖：第一版无消息队列，记录保存由后端同步写入云端 MySQL。
- 外部系统依赖：第一版无外部医疗系统依赖。
- 关联说明：该模块通过记录中心统一组织宫缩、体重、血压和症状入口，通过统计页展示身体记录时间线；不代替各业务记录模块的字段语义。
