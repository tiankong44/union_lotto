# 核心业务流程
1. 前置条件：用户进入微信登录页并点击登录；小程序提交微信临时凭证，后端建立对应的用户记录并签发访问令牌。
2. 主流程步骤 1：用户新增鱼缸并填写开缸日期和容量，选择水体类型，并可同时选择水草、珊瑚、鱼、虾、检疫或繁殖主题。
2.1 分支流程：用户可输入鱼缸内侧长宽高、常用水位留空、底砂厚度和造景占比，实时查看标称容积及实际水量估算范围；用户可将估算值回填容量，也可自行修改。
3. 主流程步骤 2：用户按个体或批次建立鱼、珊瑚、植物、虾、螺、蟹等档案，记录数量、状态、资料和事件；批次支持全量或部分转缸。
4. 主流程步骤 3：用户按鱼缸选择水质检测项目，并记录数值、单位、测量时间和方法；旧日志仍可查看。
5. 主流程步骤 4：用户记录换水、喂食、用药、观察、施肥、补剂、修剪、补水、设备维护、光照和海水配制，并关联生物或照片。
6. 分支流程：用户通过底部导航切换首页、日志、影像和我的；可查看水质趋势总览、单项历史折线、照片大图和照片详情，并导出 JSON 数据。水质提醒只根据该鱼缸由用户设置的范围生成。
7. 删除流程：用户在日志详情或照片详情确认删除；日志仍被照片引用时，先在照片详情解除关联，之后才能删除日志。
8. 异常流程：登录、数据保存、照片上传或订阅消息发送失败时向用户返回明确状态；订阅额度不足时需用户重新授权。
9. 流程结果：记录保存在云端，并仅对所属微信用户开放。

# 功能清单
- 鱼缸管理：新增、编辑、归档和恢复用户自己的鱼缸资料；水体与饲养主题分别选择，并可自选水质检测指标。
- 鱼缸容量估算：按内侧长宽高计算标称容积，并使用可调整的水位预留、底砂厚度和造景扣减比例估算实际水量；结果仅作参考，不新增持久化字段。
- 微信登录：用户点击登录按钮后，通过微信临时凭证建立当前用户会话。
- 生物管理：记录鱼、珊瑚、植物、虾、螺、蟹和其他生物的个体或批次资料、数量、状态、位置及事件照片；批次转缸保留来源和目标关系。
- 日志记录：新增、编辑和查看水质检测及日常维护活动；水质测量保存数值、单位和方法，用量、水源、水量及光照时长按需填写。
- 水质趋势：按鱼缸展示用户选择的检测指标的最新值、近七日均值和历史折线；旧六项记录保持可读。
- 设备管理：保存设备状态、每日运行时长及每台设备的维护周期。
- 影像记录：新增、查看和编辑照片分类、关联对象、记录时间与备注；确认删除时同时删除照片元数据和对应云端文件。
- 页面导航：通过底部 Tab 切换首页、日志、影像和我的，并从列表进入鱼缸、生物、日志和照片详情。
- 下拉刷新：用户可在首页、日志、影像、水质趋势和设备管理页面下拉，重新读取当前云端数据。
- 提醒管理：保存统一发送时刻、提醒开关和用户订阅授权额度。
- 数据备份：导出鱼缸、生物、事件、日志、设备、水质范围、照片元数据和照片内容；分批恢复记录并逐张恢复照片，失败后可重试。

# 业务规则 & 约束
- 状态流转规则：生物状态由用户维护；鱼类可记录正常、检疫、隔离、生病、死亡或待观察，植物和珊瑚可记录生长、状态欠佳、收缩或颜色变浅。状态变化会记录事件。
- 缸型规则：淡水、海水、汽水和其他水体与水草、珊瑚、鱼、虾等主题分别保存；旧“系统类型”文字不推断为新水体或主题。归档保留历史，可由用户恢复。
- 容量估算规则：标称容积按用户输入的鱼缸内侧长、宽、高相乘后除以1000；实际水量估算默认按水面低于缸沿2厘米、底砂厚4厘米且按厚度一半折算、造景占比10%计算，并同时给出留空1至3厘米、造景扣减5%至15%的经验范围。玻璃厚度、底砂孔隙和石材体积会影响结果，估算仅供参考，用户可调整默认参数；容量仍由用户确认后保存。
- 水质记录规则：鱼缸类型只用于建议选择指标，用户自行勾选；每项测量分别保存数值、单位、时间和测量方法，空值表示未测，数值零作为有效读数保存。盐度比重、盐度千分比、TDS 等不同计量项目保持分开。本次不调整水质范围提醒或微信订阅提醒。
- 生物记录规则：个体记录数量固定为1，批次记录数量由用户维护。生物转缸写入来源和目标鱼缸；批次部分转缸会拆分为两个有事件关联的批次。
- 生物状态规则：鱼、植物和珊瑚状态由用户选择并维护；观察描述和照片关联到事件，不作自动疾病判断。
- 设备规则：设备可选择灯光、过滤、温控、二氧化碳、水泵、蛋分、滴定和自动补水等分类，并可按单台设备维护周期保存维护记录。
- 备份规则：按依赖顺序恢复鱼缸、生物、事件、日志和设备；同一恢复会话重复提交会跳过已恢复记录，完整恢复后再次选择文件会建立新副本。照片逐张恢复到共享云端文件表。
- 数量规则：换水提醒间隔为14天，水质检测提醒间隔为7天，喂食提醒间隔为1天；设备维护间隔由用户按设备设置。
- 时间规则：统一使用上海时区；接口时间格式为 `yyyy-MM-dd HH:mm:ss`；提醒使用用户设置的统一时刻。
- 刷新规则：首页、日志、影像、水质趋势和设备管理支持手动下拉刷新；日志、影像和设备列表刷新后回到第一页，并保留当前筛选条件。
- 历史趋势规则：按鱼缸展示盐度、温度、pH、NO₂、NO₃、PO₄记录，支持最近7天、30天、90天和全部记录范围；单项趋势提供最新值、近7天均值和最近两次有效记录的变化方向，少于两次时显示记录不足。趋势仅描述用户自己的历史记录，不生成固定阈值或诊断结论。
- 权限规则：所有记录按微信用户隔离；客户端不得指定其他用户编号；照片内容读取前校验照片归属。
- 删除规则：日志仅允许所属用户删除；仍有影像记录引用时拒绝删除，用户需先在照片详情解除关联。日志表没有状态字段，状态类删除条件待补充。
- 影像规则：照片编辑保存分类、关联对象、上海本地记录时间和备注；删除影像时删除其元数据及对应共享云端文件。
- 禁止事项：不使用未由用户配置的海缸水质阈值；不把原型示例数据写入真实用户数据；没有微信订阅额度时不承诺通知送达。
- 补充约束：订阅模板编号、模板字段、AppID、服务端密钥和 API 域名待补充；提醒发送依赖用户主动订阅。

# 核心数据 & 表结构
- 核心表：

| 表名 | 用途 | 关键字段 | 字段含义 | 关联关系 |
| --- | --- | --- | --- | --- |
| `reef_user` | 微信用户身份映射 | `id`、`openid` | 内部用户编号和微信用户标识 | 被海缸业务表通过 `user_id` 关联 |
| `reef_tank` | 鱼缸资料 | `user_id`、`name`、`started_at`、`water_type`、`themes`、`enabled_metrics`、`archived` | 所属用户、基本资料、水体、主题、用户选择的水质指标和归档状态 | 一个用户可有多个鱼缸 |
| `reef_water_range` | 用户设置的水质范围 | `user_id`、`tank_id`、`metric`、`minimum_value`、`maximum_value` | 鱼缸下各参数的用户上下限 | 归属一个用户和鱼缸 |
| `reef_biology`、`reef_biology_event` | 生物资料及事件 | `tank_id`、`tracking_mode`、`quantity`、`status`、`current_tank_since`、`event_at`、`from_tank_id`、`to_tank_id`、`related_biology_id` | 记录方式、当前数量、当前入缸日期、用户状态及转缸关系 | 一个生物可有多个事件，部分转缸事件可关联新批次 |
| `reef_log`、`reef_log_biology`、`reef_water_measurement` | 日志、生物关系和水质测量 | `tank_id`、`type`、`recorded_at`、`metric`、`measured_value`、`unit`、`method`、维护活动用量和水量 | 日常记录和逐项检测信息；旧六项水质字段保留 | 日志可关联多个生物和多项水质读数 |
| `reef_equipment` | 设备和维护资料 | `category`、`status`、`power_watt`、`maintenance_interval_days`、`last_maintained_at` | 设备类别、状态、功率和维护周期 | 设备归属一个用户，可关联鱼缸 |
| `reef_photo` | 影像记录 | `user_id`、`file_key`、`category`、`reference_id`、`recorded_at`、`note` | 用户照片分类、共享文件编号、关联对象、记录时间和备注 | 照片可关联日志或业务对象 |
| `reef_reminder_preference`、`reef_reminder_setting` | 提醒偏好和开关 | `send_time`、`type`、`enabled` | 统一提醒时刻及各类提醒状态 | 按用户保存 |
| `reef_subscription_quota`、`reef_reminder_delivery` | 订阅额度和发送任务 | `available_count`、`task_key`、`due_at`、`status` | 剩余额度及提醒发送状态 | 按用户和提醒周期保存 |
| `reef_backup_restore`、`reef_backup_mapping` | 恢复会话及旧编号映射 | `backup_key`、`entity_type`、`original_id`、`restored_id` | 按用户隔离备份恢复并支持重试 | 按用户和恢复会话保存 |

- 核心字段补充说明：照片文件内容复用 `cloud_file` 表，模块表只保存文件编号及用户归属；超过16位的数据库编号通过接口以字符串传递。
