# 业务定位 & 作用
- 模块职责：为微信小程序用户记录鱼缸、生物、设备、日志、水质和影像，并管理用户设置的提醒。
- 解决的问题：待补充
- 不做会怎样：用户无法在小程序中集中查看和维护自己的海缸记录。
- 目标用户/使用角色：海缸日记微信小程序用户；其他使用角色待补充。

# 核心业务流程
1. 前置条件：用户通过微信小程序登录，后端建立对应的用户记录。
2. 主流程步骤 1：用户新增鱼缸并填写开缸日期、容量和系统类型。
3. 主流程步骤 2：用户在鱼缸下记录生物、设备和生物事件。
4. 主流程步骤 3：用户新增水质检测、换水、喂食、用药或观察日志，并可关联生物和照片。
5. 分支流程：用户查看水质趋势、影像记录和 JSON 数据导出；水质提醒只根据该鱼缸由用户设置的范围生成。
6. 异常流程：登录、数据保存、照片上传或订阅消息发送失败时向用户返回明确状态；订阅额度不足时需用户重新授权。
7. 流程结果：记录保存在云端，并仅对所属微信用户开放。

# 功能清单
- 鱼缸管理：新增和更新用户自己的鱼缸资料。
- 生物管理：记录生物资料、分类、状态和事件时间轴。
- 日志记录：保存日志类型、时间、备注、生物关联和水质测量值。
- 水质趋势：按鱼缸和参数展示历史测量值，并检查用户设置的上下限。
- 设备管理：保存设备状态、每日运行时长及每台设备的维护周期。
- 影像记录：保存照片元数据并从共享云端文件服务读取图片。
- 提醒管理：保存统一发送时刻、提醒开关和用户订阅授权额度。
- 数据导出：导出当前用户的 JSON 记录和照片元数据，不包含照片二进制内容。

# 原始业务需求
- 业务方原话：新增“海缸日记”微信小程序，包含我的鱼缸、鱼缸详情、生物详情、新增日志、水质趋势、设备管理、全部日志、设置与提醒、影像记录九个主页面，并复用当前后端。
- 需求背景：用户提供的文字页面规格和原型图；原型中的鱼缸、日志及照片仅为示例，不代表真实业务数据。
- 用户角色：多人使用，使用微信登录并按用户隔离数据。
- 业务目标：记录和查看个人海缸资料；提醒按用户设置和微信订阅额度运行。
- 提出时间：2026-11-05

# 业务规则 & 约束
- 状态流转规则：生物状态由用户维护，取值为正常、检疫中、隔离中、生病、阵亡；状态改变会记录事件。
- 数量规则：换水提醒间隔为14天，水质检测提醒间隔为7天，喂食提醒间隔为1天；设备维护间隔由用户按设备设置。
- 时间规则：统一使用上海时区；接口时间格式为 `yyyy-MM-dd HH:mm:ss`；提醒使用用户设置的统一时刻。
- 权限规则：所有记录按微信用户隔离；客户端不得指定其他用户编号；照片内容读取前校验照片归属。
- 禁止事项：不使用未由用户配置的海缸水质阈值；不把原型示例数据写入真实用户数据；没有微信订阅额度时不承诺通知送达。
- 补充约束：订阅模板编号、模板字段、AppID、服务端密钥和 API 域名待补充；提醒发送依赖用户主动订阅。

# 核心数据 & 表结构
- 核心表：

| 表名 | 用途 | 关键字段 | 字段含义 | 关联关系 |
| --- | --- | --- | --- | --- |
| `reef_user` | 微信用户身份映射 | `id`、`openid` | 内部用户编号和微信用户标识 | 被海缸业务表通过 `user_id` 关联 |
| `reef_tank` | 鱼缸资料 | `user_id`、`name`、`started_at`、`capacity_liter` | 所属用户、名称、开缸日期和容量 | 一个用户可有多个鱼缸 |
| `reef_water_range` | 用户设置的水质范围 | `user_id`、`tank_id`、`metric`、`minimum_value`、`maximum_value` | 鱼缸下各参数的用户上下限 | 归属一个用户和鱼缸 |
| `reef_biology`、`reef_biology_event` | 生物资料及事件 | `tank_id`、`status`、`event_at` | 生物所属鱼缸、用户状态和事件时间 | 一个生物可有多个事件 |
| `reef_log`、`reef_log_biology` | 日志和关联生物 | `tank_id`、`type`、`recorded_at`、水质字段 | 日志类别、时间及水质数值 | 日志可关联多个生物 |
| `reef_equipment` | 设备和维护资料 | `category`、`status`、`maintenance_interval_days`、`last_maintained_at` | 设备类别、状态和维护周期 | 设备归属一个用户，可关联鱼缸 |
| `reef_photo` | 影像记录 | `user_id`、`file_key`、`category`、`reference_id` | 用户照片元数据及共享文件编号 | 照片可关联日志或业务对象 |
| `reef_reminder_preference`、`reef_reminder_setting` | 提醒偏好和开关 | `send_time`、`type`、`enabled` | 统一提醒时刻及各类提醒状态 | 按用户保存 |
| `reef_subscription_quota`、`reef_reminder_delivery` | 订阅额度和发送任务 | `available_count`、`task_key`、`due_at`、`status` | 剩余额度及提醒发送状态 | 按用户和提醒周期保存 |

- 核心字段补充说明：照片文件内容复用 `cloud_file` 表，模块表只保存文件编号及用户归属；超过16位的数据库编号通过接口以字符串传递。
