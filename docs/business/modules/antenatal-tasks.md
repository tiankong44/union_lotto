# 产检待办模块

# 模块基本信息
- 模块编码：`antenatal-tasks`
- 模块名称：产检待办
- 所属业务域：孕期健康记录
- 负责人：待补充
- 当前版本：v1
- 更新时间：2026-08-06
- 依赖模块：孕期助手、云端 MySQL、提醒

# 业务定位 & 作用
- 模块职责：记录产检计划、已完成事项、复诊日期和个人待办。
- 解决的问题：降低遗忘产检或孕期事项的风险，形成孕期时间线。
- 不做会怎样：用户无法在同一处管理产检安排和记录状态。
- 目标用户/使用角色：孕妇本人，首版只有一个使用者。

# 核心业务流程
1. 前置条件：用户已进入单用户工具。
2. 主流程步骤 1：新增产检或待办，填写标题、计划时间和备注。
3. 主流程步骤 2：按计划时间展示待办，并允许标记完成或取消。
4. 主流程步骤 3：记录直接保存到云端 MySQL，提醒按用户设置触发。
5. 主流程步骤 4：用户可在历史列表逐条确认删除待处理或已完成事项，删除时同步清理关联提醒设置。
6. 分支流程：用户可编辑、延期或补录已完成事项。
6. 异常流程：提醒权限关闭时仅保留页面内待办状态；云端保存失败时保留当前表单并提示重试。
7. 流程结果：形成可按日期查看的产检和待办时间线。

# 功能清单
- 产检计划新增、编辑、完成、取消和删除。
- 自定义待办和备注。
- 历史列表补充、修改和清空待办备注。
- 历史列表逐条确认删除待办，并清理对应提醒设置。
- 日历/时间线查看。
- 提醒时间设置和权限状态提示。
- 与孕周、健康记录和导出功能关联。

# 原始业务需求
- 业务方原话：希望增加查看、统计、分析等完整功能。
- 需求背景：完整孕期助手需要承载产检和事项管理。
- 用户角色：单一使用者。
- 业务目标：将孕期重要事项纳入同一条时间线。
- 提出时间：2026-08-06。

# 业务规则 & 约束
- 状态流转规则：业务状态为待处理、已完成或已取消；云端请求状态为保存中、已保存或保存失败。
- 金额 / 数量规则：无金额；提醒提前时长必须为非负整数，默认值待补充。
- 时间规则：计划时间和提醒时间按用户本地时区处理。
- 备注规则：待办录入页保留可选备注，历史列表支持备注补充、修改和清空。
- 删除规则：待办仅允许 `TODO` 或 `DONE` 状态进入删除流程，按当前单用户客户端编号定位；删除前需要确认，失败时保留列表项。
- 权限规则：首版只有一个使用者，不建立用户隔离字段。
- 禁止事项：不把系统待办当作医疗机构的正式预约，不替代医生安排。
- 补充约束：提醒渠道、系统权限和默认事项模板待补充。

# 核心数据 & 表结构
- 核心表：

| 表名 | 用途 | 关键字段 | 字段含义 | 关联关系 |
| --- | --- | --- | --- | --- |
| `antenatal_task` | 产检待办 | `title`, `task_type`, `planned_at`, `status` | 待办内容和状态 | 单用户记录 |
| `reminder_setting` | 提醒设置 | `task_id`, `remind_at`, `enabled` | 提醒时间与开关 | 关联待办 |

- 核心字段补充说明：
  - 待办删除前检查 `reminder_setting.task_client_record_id` 逻辑引用；删除主记录后同步清理提醒设置，时间线使用主记录查询结果，不单独保留待办副本。

# 关联模块 & 上下游
- 上游模块：孕期助手、孕期档案、云端 MySQL CRUD 接口。
- 下游模块：提醒、时间线、导出和统计概览。
- 接口依赖：待办增删改查、完成状态更新、记录备注更新和记录删除接口。
- 消息队列 / 事件依赖：第一版无服务端消息队列，提醒由前端能力承载，待办内容保存到云端 MySQL。
- 外部系统依赖：设备通知权限，具体平台能力待补充。
- 关联说明：事项是用户自定义记录，不代表医疗机构正式指令。
